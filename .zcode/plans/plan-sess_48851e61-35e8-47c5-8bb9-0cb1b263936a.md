# 对齐 dsh Desktop 0.1.7 功能——升级 + 四项新功能

## 调研结论（已完成）

- Desktop 版 = dsh **0.1.7-rc.2**（Electron 壳 + 完整 0.1.7 包树）；主窗口 UI 与 `dsh web` 同源，差异在包差与桌面壳
- **升级可行性已逐端点验证**：gui4dsh 在用的全部 RPC/流协议/事件词表在 0.1.7 全部存活；唯一删除的 `agentPresets/copy|deletePreset` 从未被调用；compat 探针 + 自动回滚兜底在位
- 0.1.7 在 npm `next` 标签（latest 仍 0.1.5-rc.3），需显式安装 `@deepseek-ai/dsh@0.1.7-rc.2`
- 不补的（不可投影/明确不做）：托盘/自动更新/深链/快捷键/内嵌浏览器（纯桌面壳）、语音输入（用户此前明确移除）、Office 技能与 Agent Teams（分别依赖桌面捆绑运行时/实验特性，列为后续可选项）

## 实施步骤

### 第 1 步：升级 dsh 0.1.5-rc.2 → 0.1.7-rc.2
1. `npm install @deepseek-ai/dsh@0.1.7-rc.2 --workspace server`（显式版本，caret 解析不到）
2. 升级前记录 compat 探针基线（session.list / workspace.list / agentPreset.list / session.models）
3. 重启网关 → 跑 compat 探针 → 失败则自动回滚（机制已在位）
4. 全量回归套件重跑（21 项 API + 浏览器视图遍历）
5. `server/package.json` 版本声明同步为 `^0.1.7-rc.2`；updater 的版本源改为读 dist-tags（避免 latest 永远停在 0.1.5），autoUpdateDsh 保持关闭不变

### 第 2 步：每轮文件变更（workspace-changes）
- 0.1.7 新增 `workspace/changes` 投影；控制流适配层已泛化透传，直接可用
- UI：在"本轮产出"条旁增加"本轮变更"——本轮新增/修改/删除的文件列表（M/A/D 状态标记），点击同 deliverables 复制路径

### 第 3 步：会话内交互终端
- 后端：0.1.7 `dsh-api-terminal` RPC（terminal/view 等）加入网关白名单与透传
- 前端：文件侧栏加"终端"页签（xterm.js 经 WS 桥到 terminal 流），右栏"文件/终端"双 tab；终端不可用时显示 `terminal/unavailable` 事件的原因

### 第 4 步：插件管理器
- 白名单加 `pluginManager.*`（0.1.7 `dsh-plugin-manager` 的 RPC：list/install/enable/disable 等，以实际 host 描述为准）
- 设置页新增"插件"标签：插件清单卡片（名称/版本/启停开关/安装进度/重试），对齐 desktop 的 Plugins 面板

### 第 5 步：DeepSeek 官方账号登录
- 白名单加 `account.*`（0.1.7 `dsh-api-account-controller`）；PKCE 授权用浏览器跳转替代桌面原生窗
- 设置 → 模型与工具页新增"DeepSeek 账号"卡：登录态、登录按钮（跳转平台授权）、usage 摘要

### 第 6 步：验证收尾
- 每步完成后跑对应端到端验证（终端可交互、变更列表随回合出现、插件启停生效、账号状态显示）
- 最终全量回归 + 提交推送 GitHub；版本升 0.2.1 并重新打包（npm 发布与否由用户另行决定）

## 风险与边界
- 升级失败 → 自动回滚 + 人工分析（不涉及任何系统级操作，绝不触碰 RDP/网络死线）
- 0.1.7 会话表格式升级（v3→v4）由 dsh 自迁移，gui4dsh 无感
- 全程不碰：系统服务、网络配置、自动更新开关（保持关闭）
